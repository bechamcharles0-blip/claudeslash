CRITICAL DECISIONS & RATIONALE
================================================================================

1. 6-Node Redis Cluster (not single pod)
   Why: HA requirement, handles 700M+ RPM, replication redundancy
   Cost: $100/month (minimal vs API cost)
   Alternative rejected: Single Redis - doesn't meet 99.9% SLO

2. Single PostgreSQL Pod (not multi-replica)
   Why: Analytics data (eventual consistency OK), RDS would cost more
   Backup: Daily snapshots to S3 (achieves 99.9% RTO)
   Alternative rejected: RDS would be 30% more expensive

3. Asymmetric HPA (0s up, 300s down)
   Why: Responsive to spikes, preserves warm capacity
   Pattern: Proven by Hotstar at 700M+ RPM scale
   Alternative rejected: Symmetric scaling causes cost thrashing

4. 5 Metrics for HPA (not just CPU)
   Why: CPU alone doesn't capture I/O, cache misses, upstream delays
   Metrics chosen: CPU, Memory, RPS, P99 Latency, Redis Queue Depth
   Pattern: Dream11 uses 4+ metrics at scale
   Alternative rejected: CPU-only missed 30% of load anomalies

5. NetworkPolicies for Security
   Why: Pod-to-pod isolation, explicit allow lists
   Impact: Slight performance overhead (<5%)
   Alternative rejected: No policies = security risk
